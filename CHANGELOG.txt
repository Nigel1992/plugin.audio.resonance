Resonance Version 1

v1.2.2 - 2026-10-27

- Account and status is simpler: each topic has one row that shows its state.
  Tapping the row starts the next step (pair playback or sign in).
- After pairing from Account and status, browser sign-in starts directly when
  it is still missing.
- The home menu shows the next setup step at the top while setup is open.
- Playing a track without sign-in shows a clear message instead of nothing.
- The old Set up Spotify route now starts the guided setup, so the Client ID
  is always asked first.
- Pairing and sign-in messages are clearer. The pairing screen says that music
  starts when you press play in Spotify.
- Menus, dialogs and notifications are translated into English, Dutch, German,
  Spanish, French and Hebrew. Log messages, Spotify's own error texts and the
  release notes stay in English.
- Setup texts that were only in English are now translated.

v1.2.1 - 2026-10-27

- Guided setup: asks to finish setup when Resonance is not fully signed in,
  once per Kodi session, and can be rerun from Settings > Account > Run
  guided setup. An interrupted setup resumes where it stopped.
- The guided setup covers the Spotify Client ID, playback pairing over
  Spotify Connect, and browser sign-in. Each step reports its result in a
  dialog, followed by a summary. Notifications are not used for setup.
- The Spotify Client ID is kept in the setting and in a backup file in the
  add-on data folder, so a value lost from Kodi's settings file is restored.
- Home and Account and status show the next missing setup step.
- Removed the "Set up Spotify" entries; the guided setup replaces them.
- Reset Resonance (Settings > Account): moves sign-in, cache and runtime
  files into a backup folder. Restart Kodi afterwards.
- Pairing during setup does not start playback. A paused track selected by
  Spotify connects without opening the stream.
- Spotify Connect audio that stalls for 10 seconds restarts the receiver.
- Repeated Spotify pairing rejections restart the pairing receiver once.
- Connect buffer, reader and event logging moved to debug level.
- A second guided setup no longer starts while one is already open.
- Fixed a busy spinner left on screen after the setup sign-in step.
- Packaging: the zip no longer contains the add-on's dist folder, .gitignore
  or TODO.md.

v1.2.0 - 2026-10-23

- Added Spotify Connect audio support to LibreELEC/Linux ARM64 using Kodi's
  VideoPlayer, matching the Android path.
- Rebuilt the Linux spotty helper with the Connect audio bridge.

v1.1.8 - 2026-10-22

- Run setup and login dialogs outside Kodi's folder callback. Finish the
  directory first so returning to the main menu cannot leave a busy spinner.
- Defer release notes until the menu is loaded. Internal settings changes
  no longer refresh that menu while it is being built, avoiding invalid
  directory handles and a native Kodi crash on the Fire Cube.

v1.1.7 - 2026-10-22

- Built the Android ARMv7 playback helper with the same protocol compatibility
  and Connect audio bridge as the AArch64 helper, supporting 32-bit devices.
- The Android build script accepts RESONANCE_ANDROID_ARCH=armv7.

v1.1.6 - 2026-10-22

- Connect live audio now uses Kodi's VideoPlayer streaming engine. PAPlayer
  stuttered on the real-time WAV stream even with correct PCM delivery.
- Buffered the receiver pipe and removed per-frame process polling.
- Restore song title and artwork when the streaming player starts.

v1.1.5 - 2026-10-22

- Fixed Connect audio stopping immediately when Kodi opens an additional
  HTTP reader while preparing playback. Each reader now has an independent,
  bounded audio buffer; closing a probe no longer ends the playing stream.
- Added a startup audio reserve and increased the bounded Connect buffer
  to tolerate short scheduling delays during playback.
- Native Connect decoding now runs with a three-second reserve ahead of
  real time so Kodi's prebuffering does not exhaust the available audio.

v1.1.4 - 2026-10-22

- Added Spotify Connect audio routing to Kodi on Android AArch64. After
  pairing, select Kodi-Resonance in Spotify Desktop or mobile to play through
  Kodi. Desktop play/pause, track changes, seek and volume use the receiver.
- Connect audio uses a paced PCM pipe and a bounded loopback stream. Playback
  commands and track details are framed separately from audio bytes.
- Kodi pause/resume/stop are forwarded to the receiver. Starting another Kodi
  item releases the Connect session. Existing in-addon track playback remains.

v1.1.3 - 2026-10-22

- Rebuilt the Android AArch64 playback helper with a consistent desktop
  protocol identity. Spotify rejected the previous Android identity after
  successful pairing, leaving track playback waiting indefinitely for audio.
- Enabled helper error logging and included mDNS support in the new build.
- Included pinned source revision, source patch, license and rebuild script.

v1.1.2 - 2026-10-22

- Restore the setup screen's missing receiver-start function. Pairing requests
  go through the service instead of starting a second receiver in the UI.
- Use the bundled legacy Android authentication helper for Spotify Connect
  pairing, token creation, and receiver restarts. The Android playback helper
  passes its self-test but exits immediately when used for initial pairing.
- Keep the separate Spotty 2 helper for Android track playback.

v1.1.1 - 2026-10-22

- Fixed a crash on Kodi 21 that stopped the Spotify pairing screen from opening.
- Fixed the Spotify Connect pairing on Android and Linux. The box now stays
  visible in the Spotify app.
- The pairing receiver no longer stops writing its log when its output
  buffer fills up. Output goes to device-connect.log in the runtime folder.
- A receiver that refuses to start now reports the tail of its log, so users
  and admins can see why it failed.
- A receiver that cannot start is no longer restarted every few seconds.
  Automatic retries wait 15, 30, 45 and 60 seconds, and the pairing screen can
  still ask for an immediate attempt.
- A leftover receiver from an earlier Kodi session is now cleaned up on
  Linux and Android as well. It kept the discovery port busy and made every
  new receiver exit immediately.
- The pairing now falls back to the plain Spotify discovery mode when the
  dedicated authentication mode refuses to start. Both modes publish the same
  service and store the same credentials.
- The Android receiver no longer asks for the ALSA sound card, which does not
  exist on Android.
- The pairing screen starts the receiver itself, so it no longer depends on the
  background service noticing the request.

v1.1.0 - 2026-10-22
Resonance Version 1

v1.1.0 - 2026-10-22

This release replaces the earlier 1.1.0 build and contains every change since
1.0.3.

- Added Your Spotify Library with Liked Songs, Saved Albums, Followed Artists and Saved and Followed Playlists views.
- Added Spotify write actions: like or unlike a track, save or remove an album from the Spotify library, add a track to a playlist owned by the account, remove a track from one of those playlists, and unfollow a playlist or an artist.
- Removing a track from a playlist now happens inside that playlist. The context entry is named **Remove from <playlist>** and removes the track from the playlist the page belongs to, so there is no playlist picker and the action only shows where the track really is in a playlist of your own.
- Added the option to create a Spotify playlist. Choose **Create playlist...** in **Your Spotify Library** for an empty playlist, or **Create playlist with this track...** in a track context menu to start a playlist with that track. New playlists are created with the private flag, which Spotify only allows with the playlist modification permission, and appear in **Saved and Followed Playlists** once the list refreshes.
- The track and album context menus now show only the action that changes something: Like on Spotify is hidden for a track that is already liked, Unlike on Spotify is hidden for a track that is not, and Save album on Spotify is hidden for an album that is already saved. Both actions return when Spotify cannot answer the check.
- The library state is read with GET /me/library/contains, so one request per page decides the whole context menu. Liked Songs and Saved Albums need no request at all.
- Creating a playlist uses POST /me/playlists, so the account needs the playlist modification permission.
- Added bundled menu icons for every row, so the menus look the same in every skin and no longer depend on skin-specific Default*.png artwork.
- The Account and status page is regrouped into Account, Catalogue, Playback and Maintenance sections with one icon per row and short labels.
- The Playback status page was reworked to match, with the account state in its own section.
- Added a release notes window. After every update Resonance shows the version and everything that changed in a big window. The same window is always available under Account and status with the row **What's new**.
- Fixed the artist context menu. The entries **Artist: everything**, **Artist: top songs**, **Artist: albums**, **Artist: singles** and **Artist: appears on** work again. Spotify rejects an artist album page with more than ten entries per page, so the page size is capped at ten now.
- Fixed the context menu of a track. **Add to Spotify playlist** and **Create playlist with this track** did nothing, because Kodi starts a context menu entry as a script and hands over the handle -1. The add-on stopped there instead of running the action. The other context menu entries of a track, album and playlist were affected in the same way and work again.
- The rows of the playback status page only carry information. They cannot be clicked any more, so nothing happens by accident. Only the Quality row and the Connect row react to a click.
- The unpaired state of the playback status page now starts the same pairing flow as the Connect row.
- Removed the local Kodi Favorites. Spotify library writes now cover the same need directly.
- Removed the playlist search category. Spotify never shares playlist contents with followers, so a playlist search could only list playlists Resonance cannot open.
- Removed the Open Spotify link row from the main menu. Spotify links still open through the open_link action, for example from a Kodi favourites entry.
- Playlists you own are now listed across every page of your playlists, not only the first 40.
- Upgrading from 1.0.x needs one Reauthorize Spotify from Account and status, so Spotify can approve the new library and playlist permissions.
- Documented the write actions, the library endpoints and the new account page in the README.
- Fixed the catalogue tests that still expected the older request behaviour. The whole test suite passes again.

v1.0.3 - 2026-10-20

- Added local Kodi Favorites for songs, albums, artists and playlists, grouped into Albums, Artists, Playlists and Songs sections.
- Favorites are saved as local references and metadata in the add-on profile; they do not write to, download from or sync with Spotify. Clearing the catalogue cache preserves Favorites.
- Added a context-menu action to play a playlist from a selected track through the remaining playlist.
- Added a playback status page showing the current Kodi track, configured quality and Spotify Connect pairing.
- Improved catalogue responsiveness by caching playlist pages and reusing track metadata.
- Followed and collaborative playlists are marked in the list. Opening a playlist Spotify blocks now explains the limitation and offers hide, QR and refresh options.
- Added a hide-unreadable-followed-playlists option from the playlist help flow.
- Updated search navigation to retain the entered query when returning from a browsed item.
- Documented local Favorites behavior and Spotify Web API limitations.
- Spotify library write actions are not included. Spotify migrated library writes to `PUT /me/library` in its February 2026 API changes; local Kodi Favorites do not use that endpoint.

v1.0.2 - 2026-09-23

- Added artist context menus from track, album and artist rows.
- Added artist top songs, albums, singles, appears-on and combined artist overview pages.
- Artist top songs falls back to a Spotify search when the top-tracks endpoint is unavailable.
- Removed related artists after live testing confirmed Spotify returns HTTP 403 for this app.
- Changing the unreadable-playlist toggle now clears both catalogue data and addon runtime caches before refreshing the current menu.
- Added regression coverage for artist browsing endpoints.

v1.0.1 - 2026-09-23

- Hotfix: preserve the Spotify browser-login refresh token when Spotify refresh responses omit a replacement token.
- Prevents the catalogue sign-in from requiring the zip1/browser login again after access-token expiry and addon restarts.
- Added the option to hide playlists Resonance cannot read.
- Changing the unreadable-playlist toggle clears the catalogue cache, notifies the user and refreshes the current menu.
- Added regression coverage for refresh responses that only return a new access token.

v1.0.0 - 2026-09-22

- Initial Version 1 release of Resonance for Kodi.
- Search, playlists, albums, artists, links and track metadata use the browser PKCE token.
- Playback remains handled by Device Connect and the bundled Spotty/librespot helpers.
- Added browser PKCE sign-in through the hosted Resonance callback relay.
- Added Device Connect pairing for playback.
- Added persistent catalogue caching and shared Spotify API cooldown handling.
- Added loopback audio streaming into Kodi.
- Uses the regular Spotify Web API catalogue only.
- Supported target is LibreELEC on Raspberry Pi ARM/AArch64; Android ARM is experimental.
- Windows, macOS and Linux x86/x64 are not supported by this release.
- Verified with the full unit test suite.
